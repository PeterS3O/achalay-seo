Dar significado al contenido, no solo publicarlo.

Los schemas son una capa de datos estructurados que explica a los buscadores qué representa cada página: una noticia, una persona, un evento, un video o una ruta dentro del sitio.

Qué son

Una traducción entre el contenido y las máquinas.

El usuario ve un artículo. El schema declara que es un NewsArticle, quién lo escribió, cuándo se publicó, qué organización lo edita y dónde se ubica dentro del sitio.

01

Comprensión

Reduce ambigüedad. Google puede relacionar páginas, autores, organización, categorías y formatos como partes de un mismo ecosistema editorial.

02

Elegibilidad

Algunos tipos habilitan experiencias enriquecidas: breadcrumbs, video, eventos o empleos. El marcado correcto habilita; no garantiza que Google las muestre.

03

Escala y consistencia

Una implementación por plantilla convierte miles de URLs en un grafo coherente sin mantener el código manualmente página por página.

Cómo generan valor

Del contenido publicado a una señal interpretable.

El valor aparece cuando el marcado coincide con lo visible, usa URLs canónicas y se genera con la misma fuente de datos que alimenta la página.

PASO 01

Contenido visible

Título, autor, fecha, imagen, jerarquía y cuerpo que recibe el usuario.

PASO 02

JSON-LD

La plantilla expresa esos mismos datos con el vocabulario Schema.org.

PASO 03

Validación

Google comprueba sintaxis, coherencia, indexabilidad y cumplimiento.

PASO 04

Search appearance

La página puede acceder a presentaciones más descriptivas en resultados.

!
Schema no sustituye al SEO técnico ni mejora rankings por decreto.

Debe describir información real y visible. El objetivo es comprensión, elegibilidad y consistencia; no “añadir etiquetas” sin una entidad clara detrás.

Primer frente

Breadcrumbs: la base transversal.

Es el único schema que puede desplegarse de forma coherente en casi todas las plantillas y, al mismo tiempo, hacer visible la arquitectura editorial del sitio.

3. Generador reutilizable

La plantilla recibe un arreglo ya resuelto por el CMS. El último elemento puede omitir item.

TypeScript / JavaScript
type Crumb = { name: string; url?: string };

export function breadcrumbSchema(pageUrl: string, crumbs: Crumb[]) {
  return {
    "@context": "https://schema.org",
    "@type": "BreadcrumbList",
    "@id": `${pageUrl}#breadcrumb`,
    itemListElement: crumbs.map((crumb, index) => ({
      "@type": "ListItem",
      position: index + 1,
      name: crumb.name,
      ...(crumb.url ? { item: crumb.url } : {})
    }))
  };
}

Reglas de calidad

Ocho decisiones que evitan una implementación frágil.

Estas reglas deben vivir en el componente o servicio común, no depender de que cada redactor conozca Schema.org.

1

Usar la taxonomía primaria

Si una nota tiene varias categorías, elegir una ruta editorial estable; no generar múltiples caminos contradictorios.

2

URLs canónicas y absolutas

Sin parámetros, redirecciones, URLs relativas ni variantes sin trailing slash.

3

Mismos nombres en ambas capas

El texto visible y ListItem.name deben coincidir, salvo recortes razonables del título final.

4

Posiciones continuas

Empezar en 1 y avanzar sin saltos. La posición representa el orden real de la jerarquía.

5

No inventar hubs

Si no existe una página “Autores”, no añadirla como nivel enlazado. Solo declarar URLs reales, 200 e indexables.

6

Último nivel sin autoenlace

La página actual se muestra como texto y puede omitir item en el último ListItem.

7

Renderizar en HTML inicial

Evitar depender de una petición cliente o de Tag Manager para una señal estable y transversal.

8

No marcar paginación como nueva jerarquía

?page=2 mantiene el breadcrumb de su categoría; “Página 2” no es una entidad editorial.

Nueva ficha editorial

El video debe ser el centro; el texto, su capa de comprensión.

No conviene pegar una transcripción automática sin editar. Cada página debe convertirse en la mejor respuesta escrita y audiovisual sobre el tema, sin inflar contenido ni duplicar lo publicado en YouTube.

01

Breadcrumb visible

Inicio › Multimedia › Tema › Título. La misma ruta alimenta BreadcrumbList.

02

H1 + bajada orientada a intención

El H1 explica el tema; número de temporada o episodio pasa al final, no lidera el snippet.

03

Reproductor prominente

Above the fold y como contenido principal. Miniatura, título y datos del embed deben coincidir con el schema.

04

Resumen ejecutivo · 80–120 palabras

Qué aprenderá el profesional, quién participa y por qué el tema importa para la industria.

05

H2 · Claves del video / episodio

Entre 4 y 7 conclusiones verificables. Sirve al usuario que todavía no puede reproducir el contenido.

06

H2 · Transcripción editada

Separar por H3 cada 2–4 minutos, con timestamps, nombres de hablantes, ortografía técnica y enlaces contextuales.

07

H2 · Sobre el especialista

Bio breve, cargo, empresa y enlace a su entidad cuando exista. No inventar autoría editorial del invitado.

08

H2 · Recursos relacionados

Enlaces a artículos de profundidad, hub temático y otras entrevistas del mismo cluster.

A

Extensión útil, no cuota

Referencia: 700–1.500 palabras únicas según la duración. Una pieza breve puede necesitar menos; nunca rellenar para llegar a un número.

B

Transcripción editorial

Corregir nombres, siglas, tecnicismos y muletillas; preservar el sentido. Añadir timestamps y headings descriptivos.

C

Metadata orientada a búsquedas

Title de ~50–60 caracteres y descripción de ~140–160; 137 titles y 131 descriptions hoy quedan fuera de esos rangos.

D

FAQ solo cuando existe

Puede añadirse como contenido útil si el video responde preguntas reales. No usar FAQPage como rutina ni esperar un rich result.
